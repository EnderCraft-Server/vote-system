# 风控指标与技术规格

> 目标：在"不禁止同一 IP 投多票"的前提下，把异常投票模式量化出来给人看。
> 系统只做打分与提示，不自动拦截——删除动作仍然要走 OAuth2 授权（见 docs/SECURITY.md）。

## 1. 数据来源与统计口径

| 项 | 说明 |
| --- | --- |
| 数据源 | votes 表（poll_id / ip / ip_text / ua_hash / created_at），只读 |
| 统计窗口 | risk.window，默认 24h（可配 1h~720h） |
| 聚合粒度 | 按二进制 ip（IPv4 归一为 IPv4-mapped，同一地址不会重复计数） |
| 最小样本 | risk.min_votes，默认 3：少于该票数直接判"低" |
| 刷新方式 | 打开「审计」页时实时计算（单次最多 5000 票），不落库、不缓存 |

不落库的原因：票量小时实时算足够快（5000 票约几毫秒），落库还要处理"删票后统计不一致"。

## 2. 指标定义

| # | 指标 | 计算方式 | 默认阈值 | 分值 |
| --- | --- | --- | --- | --- |
| M1 | 票数 volume | 窗口内该 IP 的票数 | ≥10 / ≥30 | +3 / +5 |
| M2 | 分钟峰值 burst | 任意 60 秒滑窗内的最大票数（双指针） | ≥5 | +4 |
| M3 | 投票跨度 spread | 该 IP 投过的不同 poll 数 | ≥3 | +2 |
| M4 | 节奏规律性 regularity | 相邻两票间隔的变异系数 CV = σ/μ（票数 ≥3） | <0.15 | +3 |
| M5 | UA 多样性 ua_rotation | 该 IP 出现的不同 ua_hash 数 | ≥3 | +2 |
| M6 | 缺失 UA ua_missing | 该 IP 全部票的 ua_hash 都为空 | — | +1 |

### 为什么是这几个

- **M1/M2** 对应刷票的两种形态：慢速堆量、瞬时爆发。
- **M3** 抓"到处投票"的账号型攻击（正常人对一次投票只会投一两次）。
- **M4** 最像"机器"的一条：脚本常用固定 sleep，人工投票间隔方差极大；CV<0.15 意味着间隔几乎相等。
- **M5/M6** 是低成本辅助信号：换 UA 伪装，或干脆不带 UA 的脚本。

### 分数与等级

~~~text
score = Σ(命中的指标分值)
level = high   (score >= 6)
      | medium (score >= 3)
      | low    (其它)
~~~

| 等级 | 典型组合 | 建议动作 |
| --- | --- | --- |
| 高 | M1(+5) / M2(+4)+M4(+3) / M1+M4 | 到「危险操作」按 IP 删票，并记下回执核对 |
| 中 | M1(+3) / M4(+3) / M2(+4) 单项 | 人工看展开的投票时间，确认是否 NAT 多人共用 |
| 低 | 未命中 | 不用管 |

## 3. 页面

「审计」页（/audit）顶部新增 **IP 投票统计与风控**：

~~~text
IP（展开看明细）  票数  60s峰值  涉及投票  间隔CV  风险
1.1.1.1           12    12       1         0.02    高 12
                                                    票数 12；60 秒内 12 票；投票间隔过于规律
 └ 展开：2026-11-06 15:00:01 / 15:00:04 / 15:00:07 …
~~~

- 展开项是该 IP 的**每一票时间**（升序，最多最近 200 条）。
- 判定依据直接显示在风险列下方，不需要再翻文档。

## 4. 配置

~~~yaml
risk:
  window: 24h            # 统计窗口；越大越能看总量，越小越灵敏
  min_votes: 3
  volume_warn: 10
  volume_high: 30
  burst_per_minute: 5
  poll_spread: 3
  regularity_cv: 0.15
  ua_change: 3
~~~

调参原则：

1. **先看真实分布再定阈值**：上线一周后把 /audit 里各 IP 的票数/峰值/CV 抄下来，取 P95 作 warn、P99 作 high。
2. **宁可漏报不要误报**：NAT（公司/学校/网吧）天然同 IP 多票；M2 比 M1 更能区分"多人共用"和"脚本刷"。
3. 如果开了"一 IP 一票"（limits.one_vote_per_ip: true），M1/M2/M3 恒为 1，风控退化为只看 M4~M6，建议把窗口调到 7d。

## 5. 已知局限

| 局限 | 影响 | 缓解 |
| --- | --- | --- |
| NAT 共用出口 | 同 IP 多票误判 | 看 M2 与 CV；人工确认；白名单 IP 规则 |
| UA 可伪造 | M5/M6 只能抓偷懒的脚本 | 依赖 M2/M4 行为特征 |
| 没有设备指纹 | 换 IP + 换 UA 的对手识别不到 | 需要前端指纹或身份体系，超出当前范围 |
| 实时计算 | 单次最多 5000 票 | 票量上来后改为按小时聚合落表 |
| 只展示不告警 | 发现依赖人工看 | 可接 webhook（未实现） |

## 6. 后续可加（按性价比排序）

1. **答案指纹**：同一 IP 多次提交完全相同的选项/排序 → +3（需 join vote_answers）。
2. **网段聚集**：同一 /24 内多个 IP 在 10 分钟内投同一投票 → +2（netip.Prefix）。
3. **验证码成本**：该 IP 的 captchas.attempts 均值偏高 → +1（说明在暴力试）。
4. **告警**：high 等级触发 webhook / 邮件。
